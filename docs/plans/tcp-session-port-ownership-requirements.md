# 需求卡 B：控制会话的手动端口范围、等待与归还

状态：需求方已确认以下边界，授权记录和[计划拆分](tcp-control-session-lifecycle-plan.md)。恢复的草稿仅针对重复释放与编号复用的原复现场景，不代表以下所有权模型已经实现。

## 目标与口径

**控制会话**是一次实际的 Client–Server 控制连接；同一个 Client 重连后是新会话。**端口范围登记**是分配器记录的一段本地端口的使用权，不是一个已绑定的 TCP socket。**领用端口**指从该登记借出、尚未实际归还的具体端口。撤销后续领用、关闭 socket、归还具体端口、释放整段登记是不同的动作。

Client 的手动范围按控制会话持有。先关闭领用入口，最后一个具体端口归还后才释放范围。同一 Client 的旧、新会话可以分别保有不同范围。控制连接保持响应，不因没有范围而反复重连。Server 仍按实例配置/宣布手动分配；其文件接收等待也必须绑定发来请求的控制会话。

## 路径与固定验收标准

| 路径 | 约定及可观察结果 |
|---|---|
| B-N 通知 | 新会话在自己的第一条有效 `/client_alloc_port_range` 前不继承旧策略、不默认走系统临时端口。`NO_LIMIT` 允许 OS 端口；有效数值走手动分配。相同通知不二次登记；冲突通知留下提示，保留第一条，不断线；旧会话迟到的通知无效。不能因等待范围而阻塞控制 reader。 |
| B-R 范围归属 | 范围为空闲时，断线、会话更替、稍后的显式关闭只实际释放一次；A 退出、B 复用 A 的编号，A 再关闭时 B 的原登记逐字节保留。范围内仍有借出端口时不得删登记。旧会话不再领新端口，但新会话可领取另一段不重叠的范围；若无可用范围，保留新控制连接并等待。旧端口最后归还才使旧范围可复用，不能改新会话账目。 |
| B-D 远端目标 | 配置的 `client.host` / `client.port` 始终是控制连接目标；本地手动范围为避让而移动，不得改写 `self.port` 或本应使用该远端身份的进度键。用不同范围基址的 Client 重连到原监听端验证。 |
| B-U 普通 Client 上传 | 尚未取得本会话策略/手动范围：在发 `/file` 前等，不设固定超时、不写新上传进度。已有范围、但具体端口全忙：保留先请求对端 listener、再取本地端口的顺序。两种等待在原会话结束时都唤醒并取消，不借新连接重试或建立数据连接。旧请求/握手按已有会话规则清理。等待范围或端口不占用控制 reader。 |
| B-Q 普通批量/目录 | `/multiple_file`、目录中的实际文件条目逐文件绑定原会话；尚在等并发名额的 B 不必等 A 交回名额才取消。未开始项不得因重连而首次在新连接发送；已开始项保留原进度和恢复契约。取消/异常不泄漏或多还 `file_semaphore` 的名额；同一实例的并发上限不能因会话更替翻倍。纯建目录命令不创建文件端口。 |
| B-F 原生转发/恢复 | 已准入的原生转发在旧会话等待端口时只取消本次等待。保留原 FID、跟踪开启时已有的五字段进度及路由依据；跟踪关闭不伪造新行，未发起项不冒充已准入。保留共享与一对一两种模式、接收方驱动的恢复、真实最终 ACK。普通上传无进度不等于等待线程已取消。 |
| B-I 双向普通收件 | 收到 `/file` 或目录文件条目时，Server、Client 接收方规则相同：在收件工作线程取本地监听端口，会话失效就唤醒退出，不为旧会话补开 listener。普通发送方等端口回复的既有 20 秒协商时限不变；**不增加接收方独立的 20 秒计时器**。控制连接尚存时不承诺感知对端单笔超时，不改 wire 加取消消息。 |
| B-X 扩展 | `create_temporary_server()` / `create_temporary_client()` 创建的通用临时 socket 由扩展决定何时结束，不随控制断线强关。仅对从登记领用的实际端口计账，归还前旧范围不可复用；用户自选或 OS 分配且未从范围领用的端口不伪记为借出。创建失败、正常关闭/EOF 和 `stop_event` 路径同样不得漏还或多还；不要求等待无关扩展回调。E1 的自定义 worker drain 不变。 |

## 范围、安全与非目标

产品变更限 `PyFlow/network_api/connect_tcp.py` 中的端口分配/归还、控制通知与会话更替、普通及原生转发的发送/收件等待、扩展接口内部的借还配对。采用私有的会话取消信号与条件通知；等待必须重查**原会话**及条件，不能只看实例 `running`，不能靠固定 sleep 循环作为主要取消机制。

不新增公共参数、队列/Future 接口、固定等待超时或持久化待发清单；保持端口日志格式、TCP 线路、FID/ACK、进度/加密和扩展返回值。日志记录取消或冲突原因，不输出载荷、凭据或密钥。不改 CI、依赖、coverage，不放宽既有断言。跨独立实例/进程同时申请登记的锁文件互斥、进程被终止后的锁恢复**单列**；本卡的编号复用验收是有明确先后顺序的真实分配，不把它当作跨进程并发安全证明。

风险**高**：旧会话仍持端口时删登记、晚到 `pfree` 作用到新范围、重复通知覆盖登记、等待者错过取消、固定端口回退到 OS 端口后归还了错误的端口。由独立测试对照磁盘登记、真实监听/连接、逐文件进度和最终 ACK；不只统计函数调用数。与实例启动/关闭交接的分工见[需求卡 A](tcp-terminal-start-retry-requirements.md)。
