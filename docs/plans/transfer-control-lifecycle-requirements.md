## 目标与非目标

### 已确认目标

1. 普通上传/下载及转发恢复保持原 upstream fid/child fid、完整接收路径及进度记录；不为问题二增加数据腿编号、握手字段或持久化身份迁移。
2. 会话关闭只处理该实际控制 socket 拥有的资源；不再让重连任务按 peer 扫描并关闭后来建立的新数据 socket。
3. 流式转发采用全 route 的用户暂停：任意 Source、Server、Target 可请求 pause/start，Source 作最终仲裁。一个 Target 暂停，所有 Target 停止获得新的源数据。Server 已接收的数据继续排空到 Target；保留数据 socket，不做 seek 或重握手。
4. 不采用“每个 Target 持有独立暂停锁、必须本人解除”的规则。任意端的 start 仍可经 Source 仲裁解除用户暂停。自动背压的内存硬门槛不被用户 start 清除。
5. 有效的转发恢复请求到达 Server 后，不复用旧 relay 内存内容。若旧上游数据腿仍在，关闭该旧上游及依赖它的未完成下游，丢弃对应内存，再按接收端 offset 从 Source 重放。保留控制连接、稳定 upstream fid/child fid、已落盘文件及已确认目标集合；旧 owner 收尾后再用原握手重建数据腿。
6. Client 发起转发时拒绝目标等于其自身控制端点的目标。不把“同机不同端口”或“连接 localhost Server”误当成自转发。
7. 保留发送端以真实最终 ACK 判成功的规则。EOF 再确认不重传正文；所有 Target 已确认、仅上游 ACK 失败的终态必须能重新确认，不伪造未完成目标的 ACK。单个 Target 的完成只更新该目标，不能把部分完成当作整个任务成功。
8. 正常发送仍可多目标并行；同一 route 的恢复阶段逐 Target 顺序重放，各用自己的实际落盘 offset，已完成目标不重传。

### 非目标

- 问题一不再列为待修缺陷；问题二暂缓，不增加 leg_id、恢复换新 fid 或 pause/start 代次字段；问题三是已确认特性；问题九、十、十一继续暂不处理。
- 不增加内存回放缓存、磁盘中转缓存、目标断点范围过滤或新的传输结果通道。
- 不改 CI、依赖、coverage 策略；不删或弱化测试。
- 不解决 NAT、控制端点改变后身份迁移、多进程共享进度文件及同尺寸源文件内容改变。
- 不把 pause 返回 True 当作对端确认或立即停止落盘；不保证撤回已经交给 socket 的字节。
- 不用某一个 Target 的 offset 替代其他 Target 的 offset；不为恢复阶段增加并行重放及字节范围过滤机制。

## 修改思路与确认状态

### D2：暂缓旧控制命令跨腿隔离（本轮不修）

- fid 继续表示原文件/转发任务，恢复不重分配；原接收记录、完整路径、route 和 child 映射继续使用现有 fid。
- 不实现 leg_id 分配器、端口字段、控制帧字段、file_transfer_mode 新关键字或相关测试/helper 的协议迁移；不建立其他代次隔离机制替代它。
- pause/start 和端口响应保持现有四 token 格式；原 `/file`、`/file_folder`、`/forward_item ... resume=<offset>` 及持久化模型不变。此前换新 fid 所需的 old/new 映射、rebinds、快照 version 也不实施。
- 保留现有实际控制 socket 校验、pending/unresolved 握手隔离、同 fid 占用及旧 owner 收尾；这不能被表述为已经解决同一控制会话内迟到控制消息的问题。
- 暂缓只针对问题二，不取消问题四/五的重连安全修复，也不取消问题七和八的正常控制及恢复方案。

### D4：统一为实际控制会话所有权（拟定机制，随更改计划审查）

- 复用 `_TransferHandshakeRegistry.track_socket/cancel_socket`，让会话资源只有一个登记及取消入口。
- 已知的旧控制会话退役时，取消它自己的 listener/data socket/握手及控制状态；新会话不得借 peer 地址取得旧会话之外的资源。
- 旧 worker 固定使用创建/准入时的控制 socket，不在后台重新读取全局 `self.client_socket` 或按 peer 获取替换后的 socket。这也避免旧转发恢复 worker 误用新连接。
- 拆除 `_drop_stale_transfers` 按进度表找 socket 并关闭的重复职责。保留基于旧 owner 快照的必要收尾等待；等待不得持有全局锁或阻塞需要处理握手的控制接收线程。
- 旧 finally 按原 socket、entry、record 身份释放，不能删新 owner；失败进度继续按原规则保留。

### D8：强制重建的多目标调度（已选择顺序恢复）

当前 route 的上游被多个 Target 共享。重建上游并清空旧内存时，也必须结束依赖该旧字节流的未完成下游数据腿，等待接收端收尾、落盘；保留原 fid，不能把新 offset 字节直接接到旧下游 socket。

按已选择的简化方向，恢复流程约束如下：

1. Server 对同 route 串行登记一个重建操作。先验证请求的实际会话、原始 Source、Target、fid 和 offset，再做 teardown；无效请求不得中断任何传输。
2. 关闭旧上下游数据腿、唤醒暂停/队列等待者并等待旧 owner 收尾；旧 reader/writer 不再活动后，释放该旧 relay 的内存和运行时控制状态。
3. 保留全部已完成 Target；它们不参与重传。对其他未完成 Target，分别从各自收尾后的实际文件大小取得恢复请求，不使用 Server 的发送计数猜落盘位置。
4. 一轮只服务一个 Target 的恢复请求：Source 从该 Target 的 offset 发送到 EOF；随后按已有 route 继续下一个未完成 Target 的恢复。离线 Target 保留未完成，不阻塞可服务目标，不虚报全文件成功。
5. 同 route 恢复请求在一个调度入口登记，重建中收到的请求不重复 teardown、不创建第二个 Source sender；Source 接受重放前也必须完成旧发送 owner 的收尾，不能沿用 busy 静默忽略而丢掉已触发的恢复。
6. offset == size 且仍需目标确认时走零正文 EOF 确认；所有 Target 已确认时只恢复上游完成确认，不重发已完成目标。

强制结束共享 relay 后，计划由 Server 用 `/resume_trans <child_fid> ? <origin> <target>` 查询各未完成 Target 收尾后的落盘 offset，Client 用原数值恢复形式回复；避免猜测已发出但未落盘的字节，也不增加定时重试。该查询语义与具体切换时机均随更改计划等待确认。

已确认取舍：正常发送仍可多目标并行；同 route 的恢复阶段改为逐 Target 顺序重放，换取无需共享字节范围过滤、无需内存缓存复用。用户已明确选择该调度方式；具体实现仍需另走计划与审查。

| offset 为零/EOF、最终 ACK 再次失败 | 不误清恢复记录；确认失败可再次恢复；成功清理所属记录 |

## 数据、安全和范围约束

- 所有 peer 身份由实际控制会话及现有端点规则确定，不按 fid 全局猜路由。
- 校验在 teardown 前完成；控制请求走现有加密就绪及 send_message 入口。
- 只清理所属 route 的内存和数据 socket，不关闭无关控制连接、其他 fid 或删除已落盘字节。
- 不把 socket 仍打开或 offset 等于 size 单独作为成功证据。
- pause/start 和端口响应格式、Python pause/start 签名及持久化模型不变；不新增 leg_id 或恢复换新 fid。全局暂停、转发强制恢复及 offset 查询仍改变原契约，不能声称全部向后兼容。
- 风险等级：高（协议、并发、文件恢复完整性）。当前仅授权推进至 C2；后续阶段仍须逐项人工放行，不自动提交、合并或推送。
